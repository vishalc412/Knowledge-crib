## The claim, in one line

"The release gate's red silently disables the cross-platform verify-matrix below it"

## How to apply it

When you read `gh pr checks <pr>` on a pull request in this repository, find the row whose text is the literal `verify (${{ matrix.os }}, Node ${{ matrix.node }})`. Read it as *skipped before its matrix expanded*, not as a job that ran and passed. Then read the conclusion recorded for `release-gate` in the same run — `gh run view <run-id> --json jobs --jq '.jobs[] | {name, conclusion}'` — because that row, not the matrix row, is what CI actually tested.

Never record a Windows or Node 24 fix as CI-validated while that literal row is standing — the six cells did not execute.

If you need the matrix to execute while the gate above it is red, the edge to change is the `needs: release-gate` line at `.github/workflows/ci.yml:108`, inside the `verify-matrix` job whose key sits at `.github/workflows/ci.yml:104`. Whether that edge *should* be conditioned is a policy question this record does not settle; change it deliberately.

When the matrix does next run, watch the cells the last executing run failed: windows on both Node lines and macos on Node 24, failing in `packages/core/src/embeddings/embed-install.ts` on the out-of-root `file://` import of a tmpdir embedder module. The allow-list that governs that import is configured at `packages/core/vitest.config.ts:17` (`allow: [realpathSync(tmpdir())]`), and the NOTE naming the problem is at `packages/core/src/embeddings/embed-install.ts:209`.

## What would falsify it

- Open `.github/workflows/ci.yml` and find the `verify-matrix` job carrying an `if: always()` (or `if: !cancelled()`), or no `needs: release-gate` at all. The disabling mechanism is then absent.
- Run `gh run view <run-id> --json jobs` for any CI run after 2026-09-09T17:06:17Z and see `release-gate` with conclusion `success`. The "failed in every run since" clause is then false.
- Run `gh pr checks <pr>` and see an expanded row such as `verify (windows-latest, Node 22)` in place of the template literal. The matrix executed, and the unexpanded literal is no longer the tell.
- See windows on both Node lines and macos on Node 24 pass in a matrix run. The embed-install clause is then a historical description only.
- The inverse also falsifies: see the unexpanded literal while `release-gate` is green in the same run.

## Scope — what this does NOT claim

It does not claim the cross-platform cells are currently broken. They have not run; the 3-of-5 failures describe the last run that did execute (run 34375780464, 2026-09-09T16:17:26Z), not today's state. Read the claim as *the matrix is unobserved*, not *the matrix is failing*.

It does not claim CI is dark. `release-gate` still runs and still reports; only the job beneath it is skipped.

It does not claim the release gate fails for the embed-install reason. That failure belongs to the matrix cells; the gate's own cause is not in this record.

It does not claim the unexpanded literal is a general GitHub behaviour, only that it is the tell in this repository's `gh pr checks` output, and it does not claim the `needs` edge is itself a defect.

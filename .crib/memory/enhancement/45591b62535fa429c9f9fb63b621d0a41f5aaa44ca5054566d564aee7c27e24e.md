## How to apply it

Never read a cli-package test result as a statement about the source you just edited.

1. After each edit under `packages/cli/src`, build before testing — the package's build script at
   `packages/cli/package.json:13` (the `build` row), or the repo-root `pretest` at `package.json:15`
   (the `pretest` row).
2. Do not run one suite straight through vitest and trust it: the package test script at
   `packages/cli/package.json:15` (the `test` row) performs no build, so that path executes whatever
   was last compiled.
3. For a discrimination run use the record's full order and nothing shorter: build → baseline
   green → apply the regression → REBUILD → red → restore → REBUILD → green. Both REBUILD steps
   are load-bearing; the second is what makes the restored green mean anything.
4. After each build reconcile the byte size of `packages/cli/dist/cli.js` against the baseline the
   record carries (503308). Read a moved number as a stale baseline to re-derive, not a regression.
5. Read a restored pre-fix body's green as "this test never saw the change", not "this test does not
   discriminate".

The rebuild is not optional: the record's second check is the byte-size reconciliation, and the
record states that dist equals src at baseline is confirmed by tsc leaving `dist/cli.js`
byte-identical when no source changed, so a stale bundle survives a restore silently.

## What would falsify it

- Edit `packages/cli/src/cli.ts` and run a cli suite **without rebuilding**. If it turns red, that
  suite read source, and the premise fails for that path.
- If no cli e2e suite still resolves its CLI through `dist` — the resolution the record quotes at
  `packages/cli/src/memory-migrate.test.ts:45` (the `CLI` const) — the first clause is void.
- If the `test` row at `packages/cli/package.json:15` gains a build step, or the root `pretest` at
  `package.json:15` stops running `-r run build`, the consequence expires.

## Scope — what this does NOT claim

The over-reading to guard against is "cli tests are worthless, a green cli suite is always false".
The consequence is conditional, and so is this: a false green needs both a run that bypasses the
repo-root `pretest` (so no build happened) **and** source edited since the last build. A run through
the root test entry point builds first, via the `pretest` row at `package.json:15`, so its green is
legitimate — as is a green after a rebuild with unchanged source, where tsc leaves `dist/cli.js`
byte-identical.

It also does not claim the suites are e2e for the whole package — "the cli package's end-to-end
suites" is the record's phrase; a unit suite importing source directly sits outside it. It does not
claim 503308 is an invariant or the current size; it is the baseline the record measured. It says
nothing about the product behaviour the suite asserts, only which artifact it executed.

Knowledge-crib
Project Soul for AI Agents

A local-first knowledge graph of your codebase — served to any AI coding agent over one MCP server. Agents get full architectural context (call graphs, blast radius, doc↔code links, search) in far fewer tokens, and stop making architecture-breaking changes.

Claude Code Cursor GitHub Copilot OpenAI Codex TypeScript Python PL/SQL Markdown 16 MCP Tools REQ-1: Root Resolution REQ-2: crib mcp auto-wire Local-first · Apache-2.0
🆕
What's new in this revision — REQ-1 & REQ-2

REQ-1 — Root Resolution: crib index now registers every project in ~/.crib/registry.json. crib serve resolves the right soul per workspace through a 6-step priority chain (explicit arg → --cwd → KCRIB_ROOT → CLAUDE_PROJECT_DIR → upward walk → CWD). One user-scope IDE entry can now serve every project — no per-project config needed.

REQ-2 — crib mcp: New command auto-wires the MCP server into each IDE's config file — no hand-editing JSON/TOML. Idempotent, non-clobbering, embeds the absolute which crib path. Run crib mcp install --ide claude --global once and you're done for all projects.

💡 What it is

AI coding agents burn tokens re-reading files every session because they lack durable architectural context. Knowledge-crib indexes a project once into a queryable graph (the soul), then serves it to any agent over MCP. The agent asks context, impact, query, describes and gets a token-bounded, provenance-tagged answer — no more re-reading the whole codebase.

🧠
The one-sentence model

Parse → graph → persist as a committable "soul" → build a fast index from it → serve to agents over MCP.

Two Stores

StoreWhat it isCommitted?
SoulStore Chunked JSONL graph — source of truth, cross-IDE, engine-free, diff-friendly ✓ Yes — commit .crib/*.jsonl
IndexStore Derived fast-query layer (SQLite + FTS5), rebuildable from the soul ✗ gitignore .crib/index/
~/.crib/registry.json Machine-local pointer table: absolute project path → .crib/ dir. Populated by crib index ✗ machine-local, gitignored

The deterministic core (parse / graph / impact / search) never needs a network. LLM enrichment is opt-in and off the query hot path.

📦 Installation

⚙️
Requirements

Node ≥ 20 · pnpm 9.15.0 via Corepack · macOS / Linux

1

Clone & install dependencies

$ git clone <knowledge-crib repo> ~/Documents/Knowlege-crib
$ cd ~/Documents/Knowlege-crib
$ corepack pnpm@9.15.0 install
2

Build all 7 packages

$ corepack pnpm@9.15.0 build     # builds all 7 packages → dist/
$ corepack pnpm@9.15.0 release:verify    # production release gate
3

Link the CLI globally

$ corepack pnpm@9.15.0 --filter knowledge-crib link --global

# Verify:
$ which crib      # /Users/<you>/Library/pnpm/crib
$ crib --help     # prints the command list

The global link points back at the repo's dist/. To upgrade: git pull && corepack pnpm@9.15.0 build — no reinstall. The CLI is published as two names, crib and knowledge-crib (identical).

🔍
PATH gotcha for GUI-launched clients

IDEs launched from the Finder/Dock don't inherit your shell PATH. If a client can't start the server, use the absolute path: /Users/<you>/Library/pnpm/crib

crib mcp install (§CLI) embeds the absolute path automatically to avoid this issue.

📁 Per-project Setup

$ cd /path/to/your/project
$ crib index .     # 1. full index → .crib/ + registers in ~/.crib/registry.json
$ crib status .    # 2. confirm: nodes, edges, clusters, vcsHead
#  3. auto-wire your IDE:  crib mcp install --ide all (or --global)
✅
Commit the soul, not the index

Commit .crib/*.jsonl, .crib/crib.json, and .crib/schema/ to git. Add .crib/index/ (derived SQLite) to .gitignore. The registry (~/.crib/registry.json) is machine-local — never commit it.

🔍 Root Resolution REQ-1

Path-taking commands (serve, status, update, export, viz, query) resolve the project root through a priority chain. This is what enables one user-scope IDE entry to serve every project.

1 — highest
Explicit positional arg

crib serve /abs/path — an arg other than . always wins.

2
--cwd <path> flag

Override from the command line. May appear before or after the command.

3
KCRIB_ROOT env var

Set this in scripts or CI environments to pin the project root.

4 — key for Claude
CLAUDE_PROJECT_DIR env var

Claude Code's real workspace signal. The cwd field is ignored (Claude Code issue #42883). This env var is what makes a single user-scope Claude entry serve every project.

5
Upward walk from CWD for .crib/crib.json

Handles monorepo subdirs — walks up the directory tree until it finds an indexed root.

6 — fallback
CWD

Preserves pre-REQ-1 behaviour for existing setups.

After resolution, ~/.crib/registry.json is consulted as an overlay: if the discovered root is registered with a custom .crib location, the soul is opened from there. The registry is a pointer layer, not a second store — the soul stays committed inside each project's .crib/.

⭐
Practical upshot

Run crib mcp install --ide claude --global once. From then on, every project is served through the CLAUDE_PROJECT_DIR → upward walk → registry chain — no per-project config files, no re-wiring when you start a new project.

Existing per-project entries that pass an explicit root keep working unchanged (explicit arg always wins).

ℹ️
crib query note

Positionals to crib query are the search text, not a root path. Use --cwd, KCRIB_ROOT, or let the chain pick the root from CWD.

crib mcp <install|list|remove> REQ-2

Auto-wires the MCP server into each IDE's config file. No hand-editing JSON/TOML. Idempotent (re-running is a no-op), preserves sibling servers byte-for-byte, embeds the absolute which crib path so GUI-launched IDEs that don't inherit PATH still work.

# Project-scope (committable per-repo configs):
$ crib mcp install --ide all

# User-scope (one machine-wide entry — serves every project):
$ crib mcp install --ide claude --global

# Inspect and remove:
$ crib mcp list                         # show present/absent per IDE + scope
$ crib mcp remove --ide cursor           # strip managed entry, keep siblings
FlagMeaning
--ide <claude|cursor|vscode|codex|all>IDE target (default all for install/list)
--globalWrite the user-scope config instead of the project-scope one
--bin <path>Override the embedded command (default: absolute which crib)

🔌 The MCP Server & 9 Verbs

crib serve <root> starts one MCP server over stdio. All results are token-bounded (default docLimit=3, limit=10, with truncated + cursor) and provenance-tagged (method, provenance = EXTRACTED | INFERRED, confidence, evidence) so the agent can filter to deterministic-only (extractedOnly: true).

status health check

Returns health + whether indexed. Always call this first to verify the soul is loaded.

{
  "indexed": true,  "schemaVersion": "1.1",
  "stats": { "nodes": 1576, "edges": 1831, "clusters": 104 },
  "vcsHead": "41d60f60...",
  "capabilities": { "embeddings": false, "vector": false }
}
query hybrid BM25 search

Hybrid BM25 search over code + docs. Use to find relevant symbols or doc sections by natural language.

// request
{ "q": "where is the session token issued?", "limit": 10 }

// response
{
  "hits": [{ "id": "sym:...#TokenService.issue@L88", "score": 0.81,
              "snippet": "issue(userId):Session", "clusterId": "c:auth" }],
  "truncated": false
}
context ⭐ start here

360° view for one symbol: signature, callers, callees, linked docs. The cheapest "give me everything about this symbol" call.

// request
{ "id": "sym:src/auth/AuthService.ts#AuthService.login@L42", "docLimit": 3 }

// response
{
  "node": { "signature": ..., "file": ..., "span": ..., "clusterId": ... },
  "callers": [...], "callees": [...], "docs": [...], "truncated": false
}
impact 🔥 prevents breaking changes

This is the verb that prevents architecture-breaking changes. Ask it before any refactor. dir: "up" = dependents, dir: "down" = dependencies. risk is high/medium/low by distance.

{ "id": "sym:...#login@L42", "dir": "up", "depth": 2, "limit": 10 }
// → { "affected": [{ "rel": "calls", "distance": 1, "risk": "high" }], "truncated": true }
describesdoc ↔ code links

Doc-sections linked to a symbol. Cheap, high value.

{ "id": "sym:...#login@L42", "minConfidence": 0.4 }
neighborsraw adjacency

Graph-walking primitive. dir: in / out / both.

{ "id": "...", "rel": "calls", "dir": "out", "limit": 50 }
shortest_pathpath finding

Shortest directed path between two nodes.

{ "from": "sym:...", "to": "sym:...", "maxHops": 6 }
detect_changesdiff analysis

Dry-run delta since a git ref. Read-only. Use to review a PR against the base ref.

{ "since": "<git sha>" }  // defaults to manifest.incrementalSince
extract_rulesdecision table

Flattens a PL/SQL procedure's guard-annotated CFG into a decision table. The migration deliverable.

{ "procedure": "sym:claims.pkb#process_claim@L10", "includeTables": true }

Error Shape

{ "error": { "code": "NOT_FOUND" | "NOT_INDEXED" | "AMBIGUOUS" | "BAD_ARGS" | "INTERNAL", "message": "..." } }

🛠️ IDE Client Setup updated

All four clients launch the same MCP server: crib serve. With REQ-1 + REQ-2, the recommended path is one global command, once, and you're done — no per-project files.

🚀
Fastest path (all IDEs)

Index your project, then run one of these to auto-wire everything — no hand-editing config files:

crib mcp install --ide all — project-scope configs for all 4 IDEs (committable)

crib mcp install --ide claude --global — one machine-wide entry for Claude that serves every project

Claude Code reads MCP servers from project-scoped .mcp.json (committable) or from claude mcp add (user-scoped). The global user-scope option is now the recommended path — one entry serves all projects via CLAUDE_PROJECT_DIR.

Claude Code ignores the cwd field (issue #42883). crib's resolution chain falls through to CLAUDE_PROJECT_DIR (Claude's real workspace signal) then the upward walk from CWD. That chain is also why the global no-arg entry serves every project.

Cursor reads .cursor/mcp.json (project, committable) or ~/.cursor/mcp.json (global).

💡
Portable

${workspaceFolder} resolves to the project root — the same file works in every repo.

GitHub Copilot Chat in VS Code supports MCP via .vscode/mcp.json (GA in VS Code 1.102+). Tools only run in Copilot Agent mode. VS Code user-scoped MCP config is not documented upstream, so only project-scope is offered.

🚨
Two critical differences from Cursor / Claude

Root key must be servers (not mcpServers), and type: "stdio" is required. Using mcpServers here silently loads nothing.

A
Auto-wire (crib mcp)
$ crib mcp install --ide vscode    # writes .vscode/mcp.json (servers + type:stdio)
B
Manual — create .vscode/mcp.json

  "servers": {
    "knowledge-crib": {
      "type": "stdio",
      "command": "crib",
      "args": ["serve", "${workspaceFolder}"]
    }
  }
}

Codex CLI reads ~/.codex/config.toml (user) or .codex/config.toml (project, trusted projects only). Table must be [mcp_servers.<name>] — [mcpServers] / [mcp.servers] is silently ignored.

⚠️
Codex limitation — single-project-per-entry

Codex does not interpolate ${workspaceFolder}, so each entry must embed an absolute project path. A single global Codex entry cannot transparently serve multiple projects the way Claude/Cursor user-scope entries can.

Options: (a) one project-scoped .codex/config.toml per repo (committable, after marking repo trusted), or (b) one global entry per project in ~/.codex/config.toml. This is the one IDE where the "single entry for every project" goal is not fully achievable.

A
Auto-wire (crib mcp)
$ crib mcp install --ide codex          # project: .codex/config.toml
$ crib mcp install --ide codex --global  # global: ~/.codex/config.toml
B
Manual — add to ~/.codex/config.toml
[mcp_servers.knowledge-crib]
command = "crib"
args = ["serve", "/absolute/path/to/project"]
startup_timeout_sec = 20
tool_timeout_sec = 60

Inside the Codex TUI, /mcp lists active servers and their tools.

knowledge-crib/ # pnpm monorepo packages/ soul-schema/ # JSON Schema + TS types (the contract) core/ # GraphModel, SoulStore (chunked JSONL) + IndexStore (SQLite + FTS5) parsers/ # hand-rolled recursive-descent — TS / Python / PL-SQL / Markdown / Java / C# / Go / Rust pipeline/ # extract → resolve → link → cluster → index (phased) mcp/ # one MCP server (stdio) + the MCP verbs (pure functions) cli/ # crib index|status|query|serve|mcp|update|export|viz|install-hooks ui/ # offline web viz (vendored Cytoscape) soul-reader/ # engine-free reader for SeeroFlow / external consumers docs/ # spec + this guide

Data Flow

discoverFiles → runStructure → runParse # tree-sitter per language → runResolve → runCfg # guard-annotated CFG for PL/SQL → runLink → runCluster → (runSemanticLink) # opt-in TF-IDF → commit soul # SoulStore — source of truth → buildIndex # IndexStore (SQLite) — rebuildable → register ~/.crib/registry.json # REQ-1 — pointer layer
🔒
Determinism & Provenance

The deterministic core never touches the network. Edges carry {method, provenance, confidence, evidence}. provenance: EXTRACTED is the deterministic subset; INFERRED is opt-in (semantic: true) and strictly recall-adding. Every MCP verb is a pure function over {soul, index, repoRoot, vcs?} — the server is thin wiring.
